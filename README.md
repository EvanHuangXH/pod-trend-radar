# POD Trend Radar · 建站复用手册

本包保存设计决策、应用数据快照、跨站读取示例和 GitHub 同步工作流。线上版与自托管版共用业务设计，运行时和存储方式不同。

## 从需求到发布的设计记录

| 阶段 | 实际决定与原因 | 下一个站怎么复用 |
|---|---|---|
| 明确使用场景 | 为美国 POD 新品发现服务。运营先看信号和来源，再决定是否开发。面向操作者使用中文，消费者表达保留英文。 | 写下市场、操作者、原始内容语言和一个具体决策，如“是否打样”。 |
| 区分主动发现和定向跟踪 | 免费 RSS 带来从未登记的新词；监控词表用于聚合已有兴趣。Google 热搜和民俗文章分别代表搜索事件与定性线索。 | 每个来源定义地域、采集周期、指标单位、授权状态及原文链接。 |
| 选择数据粒度 | 关键词连接一组按来源、市场、单位、周期拆分的历史序列。Google 的 500+ 保存为下限。仅在前后窗口完整可比时计算增长。 | 将“未知”保留为空。标准库、编辑决策与市场证据分别建模。自托管表结构见 docs/postgresql-schema.sql。 |
| 设计后台 | 总览串联关键词、短句、视觉参考、竞品、机会、监控和看板。手机折叠侧栏，表格在容器内横向滚动。所有设备连接同一线上状态。 | 先实现“来源 → 详情 → 收藏或登记 → 项目状态”，再增加仪表盘卡片。 |
| 设计 AI 环节 | 按证据提取翻译、可能的目标人群、礼物场景和可迁移产品。实际观察、经典表达、原创文案有独立标签。人工备注和审批单独存储。 | 测试模型是否误译兴趣术语、重复同一载体。dominoes 曾被误译为骰子，正确为多米诺骨牌。呈现可点击原文并让人复核。 |
| 设计本地 MVP | FastAPI + PostgreSQL + 独立 worker，SQLite 供开发。导入支持 CSV/Excel，任务带去重、重试、预算和缓存。 | 托管自己控制的服务器时沿用 Compose。原项目已有数据库迁移、自动化测试和备份恢复脚本。 |
| 测试 | MVP 的 11 项测试分别在 SQLite 和 PostgreSQL 通过。实测两路 RSS 各获 10 条记录，Google 重复采集新增 0 条。数据库备份恢复后仍有 20 条。 | 隔离测试数据。验收优先看采集、幂等、来源、写入保护和恢复；单独记录未验证的外部服务。 |
| 跨设备上线 | 将前端接入托管 Worker，线上使用 R2 保存状态及上传图片。条件写入使用 ETag，避免手机和电脑同时保存时静默覆盖。 | 给每个新站独立的数据前缀和权限策略，使用同一份数据契约读取公共趋势。 |
| 权限与上线记录 | 初版仅所有者可见；后续改为持链接公开访问，写入接口校验所有者。公司网络的访问排查暂缓。 | 发布前分别测试匿名读取、匿名写入被拒及所有者编辑。公开站的完整 /api/state 当前也可匿名读取，登记敏感内容前需调整读取范围。 |
| 数据同步 | 此次从正式站读取快照并校验格式，附 GitHub Actions 每日备份。历史记录由 Git 的提交版本保存。 | 当前按公开仓库配置完整快照。公开消费接口单独维护字段白名单。账号凭据、会话和构建环境无需打包。 |

## 三种数据入口

| 入口 | 用途 | 更新边界 |
|---|---|---|
| data/state.json 与 data/media/ | 线上应用可导出的完整业务集合和引用到的本站上传图片 | 每次同步读取一次状态；外部图片保留 URL、来源及作者。manifest.json 校验快照与上传文件。此格式是业务层导出，不是 R2 物理桶镜像或 PostgreSQL 转储。 |
| data/trends-public.json | 其他网站复用 Google Trends 与 Folklife Today 的研究记录 | 固定 schema_version=1，仅包含英文关键词、首次发现时间、来源、市场、周期、单位、观测日、数值和原文链接。 |
| 正式站 /api/state | 服务端需要实时状态时读取 | 包含人工项目等内部业务字段。跨域页面建议使用自己网站的服务端读取后返回所需字段。 |

## 其他网站如何调用

将 data/trends-public.json 放在其他站可访问的位置，例如新站的 /data/ 目录。以下浏览器 JavaScript 会读取前五条有来源的趋势。对于私有 GitHub 仓库，请由服务端同步或在构建时复制公共文件，访问令牌只在服务端使用。

```js
const response = await fetch('/data/trends-public.json');
if (!response.ok) throw new Error('趋势文件读取失败');
const { schema_version, keywords } = await response.json();
if (schema_version !== 1) throw new Error('趋势数据版本不兼容');
for (const item of keywords.slice(0, 5)) {
  const series = item.series[0];
  console.log(item.term, series.source, series.unit, series.observations[0]?.url);
}
```

## GitHub 同步记录

将此目录作为目标仓库的根目录。工作流文件位于 .github/workflows/snapshot.yml，可手动触发，定时计划为北京时间每日 12:20。GitHub 调度可能延迟。首次运行需仓库允许 Actions 写入内容。工作流支持公开仓库。完整快照会公开以后录入的项目、备注、销售和广告测试记录，请只登记适合公开的内容。同步任务只备份网站当时的数据。RSS 持续采集需要单独的云端任务，此次检查时站点尚无关联的采集排程。

每次改版按此格式追加记录：日期、需求、设计决定、修改的字段或页面、验证结果、线上版本、未决事项。此次公开站版本对应源码提交 7d31f51，初次托管版本为 27e9b8c。
